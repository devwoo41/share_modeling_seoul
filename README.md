# Modeling_share — 서울 창업 내비게이션 ML 부분 재현용

LLM 파인튜닝은 빼고, LightGBM 모델 두 개만 돌려볼 수 있게 만든 폴더입니다. 노트북 두 개와 데이터 파일 네 개면 됩니다.

## 1. 가장 쉬운 방법 (원본 수집 생략)

가공이 끝난 파일 4개를 받아 `Modeling_share/data/`에 넣고 노트북을 위에서부터 실행하면 끝입니다. (파일은 git에 없음. 공유 드라이브로 전달)

| 파일 | 크기 | 쓰는 노트북 |
|---|---|---|
| `features_ind_v1.parquet` + `features_ind_v1_spec.json` | 149MB | `01_상권_레이더.ipynb` |
| `survival_v1.parquet` + `survival_v1_spec.json` | 44MB | `02_가게_생존.ipynb` |

```bash
pip install pandas pyarrow numpy lightgbm scikit-learn jupyter     # 사용한 버전: pandas 3.1, lightgbm 4.7, scikit-learn 1.9
jupyter notebook   # 01, 02 순서 상관없음. 각각 1~3분
```

## 2. 원본 데이터는 어디서 왔나

전부 공개 데이터이고, 두 곳 다 **서울 열린데이터광장(data.seoul.go.kr)** 입니다.

| 데이터 | 무엇 | 받는 방법 | 키 |
|---|---|---|---|
| 서울시 상권분석서비스 | 상권 1,650개 × 분기(2021Q1~2026Q2): 추정매출·점포·길단위인구(유동)·직장인구·상주인구·집객시설·상권변화지표·아파트·소비, 상권 영역 shapefile | 연도별 ZIP 다운로드(2021~2025) + 최근 분기는 OpenAPI | ZIP 불필요, OpenAPI 필요 |
| 행정안전부 인허가 (일반음식점·휴게음식점) | 가게 68만 곳: 상호·주소·좌표·면적·업태·인허가일·폐업일 | 열린데이터광장 LOCALDATA OpenAPI (1,000행씩 페이지 수집) | 필요 |
| 지하철역 마스터 | 역 위경도 | ZIP | 불필요 |

**API 키**: data.seoul.go.kr 회원가입 → 마이페이지 → 인증키 신청(즉시 발급) → 프로젝트 루트 `.env`에 `SEOUL_API_KEY=발급키` 한 줄. 샘플키 `sample`은 5행까지만 줍니다.

**처음부터 다시 만들려면** (프로젝트 전체 저장소 기준, 수집에 몇 시간 걸림):
1. `python -m src.collect.seoul_zip --all` → ZIP 받기 (키 불필요)
2. `python -m src.collect.seoul_api --all` → OpenAPI 최근 분기 (키 필요)
3. `python -m src.collect.localdata_seoul` 와 `... LOCALDATA_072405` → 인허가 (키 필요, 재개 가능)
4. `data/03_테이블통합.ipynb` → `Preprocessing/01_features.ipynb`(상권 세트) → `Preprocessing/02_survival_features.ipynb`(가게 세트)

## 3. 모델링 세트 두 개

### ① 상권 레이더 (`01_상권_레이더.ipynb`)
| 항목 | 내용 |
|---|---|
| 한 행 | 상권 × 업종 × 분기 (469,320행, 그중 정답이 있는 448,187행으로 학습·평가) |
| 정답 | 다음 분기 매출 `y_next`. 모델은 변화량 `log1p(y_next) − log1p(y)`를 학습 |
| 피처 98개 | 매출 지난 1~4분기·전년 대비·4분기 평균/변동, 같은 업종 대비 상대 수준, 점포 수·개업률·폐업률, 유동/직장/상주인구, 지하철·집객시설, 상권 유형·자치구·분기 |
| 분할 | 시간 순. train: 타깃 분기 ≤ 2025Q2 / val: 2025Q3~Q4 / test: 2026Q1~Q2 |
| 기준선 | 지난 분기 값, 최근 4분기 평균, 작년 같은 분기 |
| 판정 | 예측 성장률 − 같은 업종 중앙값이 +15%p↑ 성장, −15%p↓ 하락, 그 사이 유지 |

### ② 가게 생존 (`02_가게_생존.ipynb`)
| 항목 | 내용 |
|---|---|
| 한 행 | 가게 1곳. 2021~2023년에 문 연 외식 가게 53,964곳 (임시 허가·면적 0·개업 30일 내 폐업은 제외) |
| 정답 | `y_2y` = 개업 후 730일 안에 폐업하면 1 (약 26%) |
| 피처 112개 | 면적, 업태/업종, 상호 특징(글자 수·'점'·숫자·법인), 같은 지번의 이전 가게 이력, 반경 100/300m 경쟁·최근 개폐업, 지하철 거리, **개업한 분기의 상권×업종 수치(①의 피처를 그대로 붙임)** |
| 외부 데이터를 가게에 붙인 방법 | 좌표 → 상권 경계 안(또는 300m 이내) / 업태 → 서울시 업종 코드 매핑표(애매하면 상호 키워드) / 개업일 → 분기 |
| 분할 | 개업연도. train 2021 / val 2022 / test 2023 |
| 기준선 | train의 업태 × 자치구 평균 폐업률 |

## 4. 나와야 하는 숫자 (test)

| 모델 | 기준선 | LightGBM |
|---|---|---|
| ① 매출 예측 MAE_log | 최근 4분기 평균 0.264 | **0.236** (약 10% 낮음, WAPE 0.121 → 0.105) |
| ① 성장/유지/하락 Accuracy | persistence 0.604 | **0.694** |
| ② 2년 폐업 AUC | 0.543 | **0.669** |
| ② 위험 상위 20%의 실제 폐업률 | 전체 26.2% | **44.6%** |

## 5. 꼭 지킬 것
- 분할은 **시간 기준**만. 무작위 KFold를 쓰면 같은 상권의 미래가 학습에 들어가 점수가 부풀려집니다.
- 가게 모델 피처에 폐업일·폐업 여부에서 나온 값을 넣지 말 것 (정답 누수).
- 데이터 파일은 git에 올리지 말 것 (`Modeling_share/data/`는 gitignore 대상으로 두는 것을 권장).
